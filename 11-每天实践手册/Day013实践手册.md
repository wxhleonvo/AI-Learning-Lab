# Day013 实践手册：本地模型初体验

> 路线位置：180 天路线 → Phase 1 → Day013
> 前置：Day001–Day012（云端 LLM / Embedding API）
> 今日主题：**把 LLM 跑在自己电脑上——用 Ollama 或 LM Studio 加载本地模型，通过 OpenAI 兼容端点接入 M.E.AI，理解本地 vs 云端的权衡**

---

## 1. 今日目标

完成后，你必须能够：

1. 说清楚 **本地模型** 的两种主流运行方式：**Ollama**（命令行 / 服务）和 **LM Studio**（GUI）。
2. 下载并运行一个本地 LLM（推荐 Qwen2.5-7B 或 Llama-3-8B 的 GGUF 量化版）。
3. 启动本地模型的 **OpenAI 兼容端点**（`http://localhost:11434/v1` 或 LM Studio 的 `http://localhost:1234/v1`）。
4. 用 M.E.AI 的 `OpenAIClient` 连接本地端点（**只改 Endpoint，不改代码结构**）。
5. 理解 **量化（Quantization）** 的概念：FP16 / Q8 / Q6 / Q4 / Q3 的精度-速度-内存权衡。
6. 对比 **本地 vs 云端** 在速度、隐私、成本、能力四个维度的差异。
7. 用本地模型跑通 Day011 的结构化输出 + Day012 的 Embedding（验证全链路本地化可行性）。

# 4. 环境准备（安装本地模型运行器）

## 方案 A：Ollama（推荐，命令行友好）

```powershell
# 1. 下载安装 Ollama for Windows
#    https://ollama.com/download/windows

# 2. 验证安装
ollama --version

# 3. 拉取一个模型（首次会下载约 4-5GB）
#    qwen2.5:7b 是中文友好的 7B 模型，Q4 量化约 4.7GB
ollama pull qwen2.5:7b

# 4. 启动 Ollama 服务（安装后默认后台运行，端口 11434）
#    如未自动启动：
ollama serve

# 5. 命令行直接对话测试
ollama run qwen2.5:7b "你好，请用一句话介绍你自己"
```

## 方案 B：LM Studio（GUI）

1. 下载安装 LM Studio：https://lmstudio.ai/
2. 打开后在「Search」里搜 `qwen2.5-7b-instruct`，选 GGUF 版本下载
3. 左侧切到「Local Server」，选模型，点「Start Server」
4. 默认端点：`http://localhost:1234/v1`，API Key 随意填（如 `lm-studio`）

## 硬件要求参考

| 模型 | 量化 | 内存占用 | 推荐显存/内存 |
|---|---|---|---|
| qwen2.5:3b | Q4 | ~2GB | 8GB 内存 |
| qwen2.5:7b | Q4 | ~5GB | 16GB 内存 |
| llama3.1:8b | Q4 | ~6GB | 16GB 内存 |
| qwen2.5:14b | Q4 | ~9GB | 32GB 内存 |

> 如果内存不够，先用 `qwen2.5:3b`，能跑通流程即可。
> 也可以选用更新的模型（如 `qwen3:8b` / `qwen3:4b`），把后文命令和配置中的模型名整体替换即可。

## 常见问题

- `ollama serve` 提示端口已被占用：说明后台服务已在运行，忽略即可。
- 连接 `localhost:11434` 被拒绝：确认 Ollama 托盘图标在运行，执行 `ollama list` 能看到已下载模型。
- `ollama pull` 下载慢：换网络重试，或改用 LM Studio 内置下载。
- 没有独显 / 内存只有 8GB：选 `qwen2.5:3b` 甚至 `qwen2.5:1.5b`，先跑通流程，实验结论不受影响。
- LM Studio 用户：默认端点是 `http://localhost:1234/v1`，模型名填你在 Local Server 里加载的模型名。

# 7. 实验二：M.E.AI 连接本地模型（只改 Endpoint）

```csharp
using System.Text;
using Microsoft.Extensions.AI;
using Microsoft.Extensions.Configuration;
using OpenAI;
using System.ClientModel;
using System.Numerics.Tensors;   // 余弦相似度 TensorPrimitives（实验六用）

Encoding.RegisterProvider(CodePagesEncodingProvider.Instance);
Console.InputEncoding = Encoding.GetEncoding(936);

IConfigurationRoot config = new ConfigurationBuilder()
    .AddJsonFile("appsettings.json", optional: false)
    .AddUserSecrets<Program>()
    .Build();

// 本地模型配置（从 appsettings.json 读，不写死）
string? localEndpoint = config["Local:Endpoint"] ?? "http://localhost:11434/v1";
string? localModel = config["Local:Model"] ?? "qwen2.5:7b";
string? localKey = config["Local:ApiKey"] ?? "ollama";

OpenAIClientOptions localOptions = new()
{
    Endpoint = new Uri(localEndpoint)
};

IChatClient localClient = new OpenAIClient(new ApiKeyCredential(localKey), localOptions)
    .GetChatClient(localModel).AsIChatClient();

Console.WriteLine("===== 实验二：M.E.AI 连接本地模型 =====");
Console.WriteLine($"  端点：{localEndpoint}");
Console.WriteLine($"  模型：{localModel}");

var sw = System.Diagnostics.Stopwatch.StartNew();
var response = await localClient.GetResponseAsync(
    "请用一句话解释什么是本地大模型。",
    new ChatOptions { Temperature = 0.1f, MaxOutputTokens = 200 });
sw.Stop();

Console.WriteLine($"  耗时：{sw.ElapsedMilliseconds} ms");
Console.WriteLine($"  回复：{response.Text}");
Console.WriteLine($"  输入 Token：{response.Usage?.InputTokenCount}");
Console.WriteLine($"  输出 Token：{response.Usage?.OutputTokenCount}");
```

> appsettings.json 已在第 5 节创建（`Local` 节点）。

### 预期结果

```text
端点：http://localhost:11434/v1
模型：qwen2.5:7b
耗时：3000-8000 ms（取决于硬件）
回复：本地大模型是指...
输入 Token：15
输出 Token：50
```

### 必须得出的结论

```text
M.E.AI 连本地模型 = 连云端模型，只改 Endpoint
代码结构完全不变（IChatClient / GetResponseAsync 都一样）
本地模型速度取决于硬件（CPU/GPU），通常比云端慢
但本地完全免费、数据不出机器
```

# 8. 实验三：本地模型跑结构化输出

验证本地模型是否支持 `GetResponseAsync<T>` 结构化输出。

```csharp
using System.ComponentModel;

Console.WriteLine("\n===== 实验三：本地模型结构化输出 =====");

try
{
    ChatResponse<ReviewAnalysis> structured = await localClient.GetResponseAsync<ReviewAnalysis>(
        "分析这条评论的情感：这个产品续航不行，失望。只输出 JSON。",
        new ChatOptions { Temperature = 0.1f, MaxOutputTokens = 300 });

    if (structured.TryGetResult(out ReviewAnalysis? r))
    {
        Console.WriteLine($"  ✅ 结构化成功：情感={r.Sentiment}, 评分={r.Score}");
        Console.WriteLine($"     关键词={string.Join("、", r.Keywords ?? [])}");
    }
    else
    {
        Console.WriteLine($"  ⚠️ 解析失败，原始：{structured.Text}");
    }
}
catch (Exception ex)
{
    Console.WriteLine($"  ❌ 本地模型不支持结构化输出或报错：{ex.Message[..Math.Min(100, ex.Message.Length)]}");
    Console.WriteLine("     （部分本地模型不支持 response_format，需降级为 RawText + 手动 JSON 解析）");
}

public enum Sentiment { Positive, Negative, Neutral }
public class ReviewAnalysis
{
    [Description("情感倾向")] public Sentiment Sentiment { get; set; }
    [Description("0-10 评分")] public int Score { get; set; }
    [Description("关键词")] public List<string>? Keywords { get; set; }
    [Description("结论")] public string? Conclusion { get; set; }
}
```

### 必须得出的结论

```text
本地模型对结构化输出（response_format）的支持参差不齐
Qwen2.5 系列支持较好，部分小模型可能不支持
不支持时：降级为 RawText + 手动 JsonSerializer.Deserialize
或者在 Prompt 里强约束「只输出 JSON」
```

# 9. 实验四：量化对比（Q4 vs Q8 vs FP16）

如果硬件允许，下载同一模型的不同量化版本，对比速度和输出质量。

```csharp
Console.WriteLine("\n===== 实验四：量化对比 =====");

// 需要提前 pull 不同量化版本：
// ollama pull qwen2.5:7b          ← 默认 Q4_K_M
// ollama pull qwen2.5:7b-instruct-q8_0
// ollama pull qwen2.5:7b-instruct-fp16  ← 可能太大

string[] quantModels = { "qwen2.5:7b", "qwen2.5:7b-instruct-q8_0" };
string testPrompt = "1+1等于几？只回答数字。";

foreach (var m in quantModels)
{
    try
    {
        IChatClient c = new OpenAIClient(new ApiKeyCredential("ollama"), localOptions)
            .GetChatClient(m).AsIChatClient();

        var sw = System.Diagnostics.Stopwatch.StartNew();
        var r = await c.GetResponseAsync(testPrompt, new ChatOptions { Temperature = 0.1f, MaxOutputTokens = 50 });
        sw.Stop();

        Console.WriteLine($"  {m,-35} 耗时={sw.ElapsedMilliseconds,5}ms  回复={r.Text?.Trim()}");
    }
    catch (Exception ex)
    {
        Console.WriteLine($"  {m,-35} 未安装或报错：{ex.Message[..Math.Min(60, ex.Message.Length)]}");
    }
}
```

### 必须得出的结论

```text
量化越低（Q4）→ 内存越小 → 速度越快 → 精度略降
量化越高（Q8/FP16）→ 内存越大 → 速度越慢 → 精度越高
7B 模型 Q4 约 4.7GB，Q8 约 8.5GB，FP16 约 14GB
日常开发 Q4_K_M 足够（精度损失肉眼几乎不可察）
```

# 10. 实验五：本地 vs 云端 四维对比

用同一个 Prompt 分别跑本地和云端，记录速度、Token、输出质量。

```csharp
Console.WriteLine("\n===== 实验五：本地 vs 云端 四维对比 =====");

string testQ = "请用三句话解释什么是 RAG。";

// 云端（复用 Day001-Day010 的配置）
string? cloudModel = config["DashScopeModel"];
string? cloudKey = config["DashScopeKey"];
IChatClient cloudClient = new OpenAIClient(new ApiKeyCredential(cloudKey!),
    new OpenAIClientOptions { Endpoint = new Uri("https://dashscope.aliyuncs.com/compatible-mode/v1") })
    .GetChatClient(cloudModel).AsIChatClient();

// 本地
var (localTime, localTokens, localText) = await Benchmark(localClient, testQ);
var (cloudTime, cloudTokens, cloudText) = await Benchmark(cloudClient, testQ);

// 注意：字符串用双引号；带对齐的插值变量先算好再放入，避免表达式里混引号
string localSpeed = $"{localTime} ms";
string cloudSpeed = $"{cloudTime} ms";

Console.WriteLine($"  {"维度",-8} | {"本地 qwen2.5:7b",-20} | {"云端 qwen3.7-flash",-20}");
Console.WriteLine($"  {"速度",-8} | {localSpeed,-20} | {cloudSpeed,-20}");
Console.WriteLine($"  {"输出Token",-8} | {localTokens,-20} | {cloudTokens,-20}");
Console.WriteLine($"  {"成本",-8} | {"免费（电费/硬件）",-20} | {"按量计费",-20}");
Console.WriteLine($"  {"隐私",-8} | {"数据不出机器",-20} | {"数据上传云端",-20}");
Console.WriteLine($"  {"能力",-8} | {"7B 量化模型",-20} | {"云端大模型",-20}");

// 输出质量人工对比：把两段回复都打印出来，自己打分
Console.WriteLine($"\n  本地回复：{localText}");
Console.WriteLine($"  云端回复：{cloudText}");

async Task<(long ms, int? tokens, string? text)> Benchmark(IChatClient c, string q)
{
    var sw = System.Diagnostics.Stopwatch.StartNew();
    var r = await c.GetResponseAsync(q, new ChatOptions { Temperature = 0.1f, MaxOutputTokens = 300 });
    sw.Stop();
    return (sw.ElapsedMilliseconds, r.Usage?.OutputTokenCount, r.Text);
}
```

### 必须得出的结论

```text
本地模型优势：免费、隐私、可离线、无 Key 过期问题
本地模型劣势：速度慢（CPU 推理）、能力弱（7B vs 云端大模型）、占内存
云端模型优势：速度快、能力强、无需本地硬件
云端模型劣势：按量计费、数据上传、依赖网络、Key 管理
生产项目：敏感数据用本地，通用能力用云端，按需路由（Phase 5 Day120 Model Routing）
```

# 11. 实验六：本地 Embedding（可选，硬件允许时）

Ollama 也支持 Embedding 模型，如 `nomic-embed-text`。验证本地 Embedding 全链路。

```csharp
Console.WriteLine("\n===== 实验六：本地 Embedding（可选）====");

// 先 pull embedding 模型：
// ollama pull nomic-embed-text

try
{
    IEmbeddingGenerator<string, Embedding<float>> localEmb =
        new OpenAIClient(new ApiKeyCredential("ollama"), localOptions)
            .GetEmbeddingClient("nomic-embed-text")
            .AsIEmbeddingGenerator();

    string[] texts = { "苹果手机", "iPhone", "今天天气好" };
    var vecs = await localEmb.GenerateAsync(texts);

    // 10.9.0 起余弦相似度在 System.Numerics.Tensors.TensorPrimitives 上
    float sim1 = TensorPrimitives.CosineSimilarity(vecs[0].Vector.Span, vecs[1].Vector.Span);
    float sim2 = TensorPrimitives.CosineSimilarity(vecs[0].Vector.Span, vecs[2].Vector.Span);

    Console.WriteLine($"  苹果手机 vs iPhone  相似度：{sim1:F3}（应较高）");
    Console.WriteLine($"  苹果手机 vs 天气好  相似度：{sim2:F3}（应较低）");
}
catch (Exception ex)
{
    Console.WriteLine($"  本地 Embedding 不可用：{ex.Message[..Math.Min(80, ex.Message.Length)]}");
    Console.WriteLine("  （可跳过，云端 Embedding 已在 Day012 验证）");
}
```
