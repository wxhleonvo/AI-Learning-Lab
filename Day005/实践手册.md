# 7. 实验一：普通响应

`Program.cs`：

```csharp
using Microsoft.Extensions.AI;
using Microsoft.Extensions.Configuration;
using OpenAI;

IConfigurationRoot config = new ConfigurationBuilder()
    .AddUserSecrets<Program>()
    .Build();

string? model = config["ModelName"];
string? key = config["OpenAIKey"];

if (string.IsNullOrWhiteSpace(model))
    throw new InvalidOperationException("ModelName 未配置。");

if (string.IsNullOrWhiteSpace(key))
    throw new InvalidOperationException("OpenAIKey 未配置。");

IChatClient client =
    new OpenAIClient(key)
        .GetChatClient(model)
        .AsIChatClient();

ChatResponse response = await client.GetResponseAsync(
    "请用中文解释什么是 RAG，并举一个企业知识库的例子。",
    new ChatOptions
    {
        MaxOutputTokens = 300,
        Temperature = 0.3f
    });

Console.WriteLine("=== 完整响应 ===");
Console.WriteLine(response.Text);
```

运行：

```powershell
dotnet run
```

观察：

> 普通调用通常等待完整结果后再处理。

# 14. 实验八：CancellationToken

```csharp
CancellationToken
```

是把“取消请求”的信号传给异步操作。

示例：

```csharp
using var cts = new CancellationTokenSource();

ChatOptions options = new()
{
    MaxOutputTokens = 1000,
    Temperature = 0.3f

await foreach (ChatResponseUpdate update
    in client.GetStreamingResponseAsync(
        "请写一篇比较长的文章，介绍企业 RAG 系统的架构。",
        options,
        cts.Token))

    Console.Write(update.Text);
}
```

当前 Microsoft API 的参数中明确包含 `CancellationToken`，用于监控取消请求。citeturn0search1

# 15. 实验九：3 秒后自动取消

```csharp
using var cts = new CancellationTokenSource();

cts.CancelAfter(TimeSpan.FromSeconds(3));

ChatOptions options = new()
{
    MaxOutputTokens = 1000,
    Temperature = 0.3f
};

try
{
    await foreach (ChatResponseUpdate update
        in client.GetStreamingResponseAsync(
            "请写一篇比较长的文章，介绍企业 RAG 系统的架构。",
            options,
            cts.Token))
    {
        Console.Write(update.Text);
    }
}
catch (OperationCanceledException)
{
    Console.WriteLine();
    Console.WriteLine("=== 请求已取消 ===");
}
```

观察：

```text
回答生成一部分
        ↓
约 3 秒
        ↓
取消
```

实际输出多少内容取决于模型、网络和响应速度。0

# 16. 实验十：为什么 Streaming 对聊天 UI 有价值？

不用写代码，先画出两种体验。

普通调用：

```text
用户发送
  ↓
等待
  ↓
等待
  ↓
等待
  ↓
完整生成
  ↓
一次显示
```

Streaming：

```text
用户发送
  ↓
第一段
  ↓
第二段
  ↓
第三段
  ↓
……
  ↓
完整回答
```

核心价值：

> 降低用户的感知等待时间。

注意：

> Streaming 不等于模型计算速度一定变快。它主要改变结果向客户端交付的方式。

# 18. 推荐最终版 Program.cs

完成实验后，可以整理成：

```csharp
using Microsoft.Extensions.AI;
using Microsoft.Extensions.Configuration;
using OpenAI;

IConfigurationRoot config = new ConfigurationBuilder()
    .AddUserSecrets<Program>()
    .Build();

string? model = config["ModelName"];
string? key = config["OpenAIKey"];

if (string.IsNullOrWhiteSpace(model))
    throw new InvalidOperationException("ModelName 未配置。");

if (string.IsNullOrWhiteSpace(key))
    throw new InvalidOperationException("OpenAIKey 未配置。");

IChatClient client =
    new OpenAIClient(key)
        .GetChatClient(model)
        .AsIChatClient();

string prompt = """
请详细解释企业级 RAG 系统的工作流程。
要求：
1. 使用中文。
2. 解释文档处理。
3. 解释 Chunk。
4. 解释 Embedding。
5. 解释向量检索。
6. 解释最终生成。
7. 控制在 500 字以内。
""";

ChatOptions options = new()
{
    MaxOutputTokens = 500,
    Temperature = 0.3f
};

using var cts = new CancellationTokenSource();

string fullText = "";
int updateCount = 0;

Console.WriteLine("=== Streaming Start ===");

try
{
    await foreach (ChatResponseUpdate update
        in client.GetStreamingResponseAsync(
            prompt,
            options,
            cts.Token))
    {
        updateCount++;
        Console.Write(update.Text);
        fullText += update.Text;
    }

    Console.WriteLine();
    Console.WriteLine();
    Console.WriteLine("=== Streaming Finished ===");
    Console.WriteLine($"Update 数量：{updateCount}");
    Console.WriteLine($"最终字符数：{fullText.Length}");
}
catch (OperationCanceledException)
{
    Console.WriteLine();
    Console.WriteLine("=== Streaming Cancelled ===");
}
```

# 26. 面试表达模板

你需要能够用自己的话解释：

> 在 .NET 的 `Microsoft.Extensions.AI` 中，`IChatClient` 同时提供普通响应和流式响应能力。普通调用使用 `GetResponseAsync`，等待完整的 `ChatResponse`；流式调用使用 `GetStreamingResponseAsync`，返回 `IAsyncEnumerable<ChatResponseUpdate>`，应用通过 `await foreach` 持续消费响应更新。这样聊天应用可以在模型还没有生成完整答案时，就逐步把内容展示给用户，从而降低用户的感知等待时间。同时可以通过 `CancellationToken` 处理取消等场景。
