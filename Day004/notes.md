## RAG（检索增强生成）

RAG 是一种将检索和生成技术结合在一起的系统，用于根据用户查询生成相关的内容，比如自定义的企业知识库。RAG 系统通常包括以下几个部分：
- **检索模块**：用于根据用户查询从知识库中检索相关的内容。
- **生成模块**：用于根据检索到的内容生成符合用户需求的响应。

## ChatOptions 说明：

- `MaxOutputTokens`：指定最大输出令牌数，默认值为 4096，包括不可见的 <think>...</think> 推理过程。
- `Temperature`：指定温度参数，默认值为 0.7。
- `TopP`：指定 Top-P 参数，默认值为 0.9。

## Temperature 核心参数：（温度）
Temperature	行为                                            适用场景   
0.0f	    贪心解码，最稳定（理论上每次都选概率最高的 token）	   代码、事实问答、API 调用
0.3f	    偏稳定，少量变化	                              分类、总结
0.7f	    平衡（多数模型默认值）	                           通用对话
1.0f	    多样性高	                                     创意写作、头脑风暴  

# Temperature 实践记录-取值：
不同模型的 Temperature 的支持的范围不同，有的模型支持 0.0f 到 1.0f，有的模型支持 0.0f 到 0.5f 甚至更小。
# Temperature 实践记录-生成内容对比：
Temperature=0.0 的五次是"同一个画家用不同笔触画同一座山"——骨架相同，风格微调。
Temperature=1.0 的五次是"五位不同画家用各自流派画五座不同的山"——只有"山"这个母题相同，其余全变。
跨Temperature对比：0.0是"硬科幻纪实"，1.0是"赛博玄学诗"。 低温让AI更接近"高级工具"，高温让AI更接近"数字神明"。

## TopP 核心参数：（Top-P）
top_p 参数，也常被称为核采样（Nucleus Sampling），其核心作用是在每一步生成时，动态地筛选出一个概率质量总和达到 p 值的最小候选词集合，然后模型只会从这个“精选”集合里进行随机选择。

可以把 top_p 理解成一个动态调整的“候选词门槛”，它不像 top_k 那样固定选前几个词，而是根据当前上下文模型对每个词的确定程度来动态决定留哪些词。

举个例子，模型预测下一个词的概率分布为：AI (36%)、科技 (32%)、奇舞 (26%)、自行车 (3%)、Hello (2%)……

当设置 top_p = 0.9 时，模型会从概率最高的词开始累加：

加上“AI”(36%)，累计 36% < 90%，保留。
加上“科技”(32%)，累计 68% < 90%，保留。
加上“奇舞”(26%)，累计 94% ≥ 90%，停止。
结果：“自行车”、“Hello”等低概率词被直接舍弃，模型在“AI”、“科技”、“奇舞”这三个词中按新的概率比例进行选择。

top_p 的不同取值直接影响输出的确定性或多样性：

参数调节	            候选池大小	效果	                                                                    典型适用场景
较低值 (如 0.1 - 0.2)	很小	   输出更确定、保守。模型基本只从概率最高的几个词中选择，文本更连贯、可预测，但缺乏惊喜。	 代码生成、数学解题、事实性问答、信息提取等需要高准确性的任务。
较高值 (如 0.9 - 0.95)	较大	   输出更多样、有创造力。模型可以考虑更多合理的词汇，从而生成更丰富、有趣的内容。	        创意写作、头脑风暴、故事生成等需要发散思维的场景。

许多模型和API会将 top_p=0.9 或 0.95 设为推荐值，在多样性和质量间取得平衡。

# TopP 与 temperature 的区别
temperature：作用于概率计算之前，通过改变概率分布的“锐利”或“平坦”程度，来影响所有词被选中的概率，低概率词仍有被选中的可能。
top_p：作用于概率计算之后，通过一个“门槛”强行截断低概率词，将它们完全排除在候选名单之外

# 一点小建议
在调参时，建议一次只调整 temperature 或 top_p 中的一个，以避免两者效果相互叠加，增加调试的复杂性。

## StopSequences 核心参数：（停止序列）
停止序列（StopSequences） 是一种"提前刹车"机制：你给模型一组字符串，模型在生成输出时，一旦发现输出里出现了这些字符串中的任意一个，就立即停止生成（停止序列本身通常不会出现在返回给你的文本里，或被截断在该序列之前）。

用途举例
格式控制：让模型生成时遇到分隔符就停，避免它继续啰嗦。
多轮对话/接力：给一个 "\nUser:" 作为 stop，防止模型自己编造下一轮用户发言。
安全裁剪：在特定标记处截断输出。

# 示例：
prompt 让模型输出三个关键词后写 END。如果不设 StopSequences，模型会完整输出
关键词1
关键词2
关键词3
END

设了 StopSequences = ["END"] 后，模型在即将输出 END 时被截断，你拿到的 response.Text 通常只剩：
关键词1
关键词2
关键词3
