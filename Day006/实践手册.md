## 1. 今日目标

今天只解决一个核心问题：

> 我不想让模型返回一段自由文本再自己用正则/字符串切割去解析；我希望它直接返回符合 C# 类型 / JSON Schema 的结构化数据。

完成后，你必须能够：

1. 说清楚“自由文本输出”和“结构化输出”的工程区别。
2. 区分三个层次：Prompt 约定 JSON → JSON Mode（`ChatResponseFormat.Json`）→ JSON Schema（`ChatResponseFormatJson`）。
3. 定义一个 C# 类型作为输出契约，并用 `[Description]` 描述字段。
4. 用 `AIJsonUtilities.CreateJsonSchema` 看到类型自动生成的 JSON Schema。
5. 使用泛型扩展方法 `GetResponseAsync<T>()` 直接拿到强类型结果。
6. 使用 `ChatResponse<T>.Result` 和 `TryGetResult`，并理解“模型不保证 100% 遵守 Schema”。
7. 把结构化输出和 Day004（`ChatOptions`）、Day005（Streaming）组合起来。
8. 说清楚结构化输出为什么是后面 RAG、Agent、ASP.NET Core API 的基础。

https://learn.microsoft.com/zh-cn/dotnet/api/microsoft.extensions.ai.chatclientstructuredoutputextensions

今天只看 `GetResponseAsync<T>` 的几组重载：

```text

GetResponseAsync<T>(IChatClient, IEnumerable<ChatMessage>, ChatOptions, bool?, CancellationToken)
```

注意那个 `bool?` 参数：`useJsonSchemaResponseFormat`，今天实验中会用到它做“回退”。

https://learn.microsoft.com/en-us/dotnet/api/microsoft.extensions.ai.chatresponseformatjson

重点：

```text
ChatResponseFormatJson
├── Schema            (JsonElement?，JSON Schema)
├── SchemaName        (string?)
└── SchemaDescription (string?)
```

以及两个内置格式：

```text
ChatResponseFormat.Text   → 纯文本
ChatResponseFormat.Json   → JSON 对象，但不携带 Schema
```

## 3.4 API：AIJsonUtilities.CreateJsonSchema

https://learn.microsoft.com/en-us/dotnet/api/microsoft.extensions.ai.aijsonutilities.createjsonschema

签名核心：

```csharp

    Type type,
    string? description = null,
    ...
    JsonSerializerOptions? serializerOptions = null)
```

作用：**从 C# 类型生成 JSON Schema**。

## 3.5 API：ChatResponse<T>

https://learn.microsoft.com/en-us/dotnet/api/microsoft.extensions.ai.chatresponse-1

重点看官方 Remarks 的原话：

> Language models are not guaranteed to honor the requested schema. If the model's output is not parseable as the expected type, then `TryGetResult` will return `false`. You can access the underlying JSON response on the `Text` property.

翻译：**模型不保证一定遵守 Schema**。解析失败时 `TryGetResult` 返回 `false`，原始文本仍然可以在 `Text` 属性拿到。这句话是今天最重要的工程认知之一。

# 7. 先理解：为什么需要结构化输出

Day001～Day005 我们拿到的都是：

```csharp
ChatResponse response = await client.GetResponseAsync(prompt);
string text = response.Text;   // 一段自由文本
```

`text` 是给**人**看的。但程序需要的是**数据**：

```text
场景：用户评论分析

自由文本（给人看）：
“这条评论整体比较正面，用户对物流很满意，但觉得包装一般。
情感倾向是积极的，关键词：物流、包装、满意……”

结构化数据（给程序用）：
{
  "sentiment": "Positive",
  "score": 8,
  "keywords": ["物流", "包装", "满意"],
  "summary": "用户对物流满意，认为包装一般"
}
```

有了结构化数据，程序才能：

```text
存数据库
    ↓
返回 JSON 给前端 / API
    ↓
走 if / switch 业务分支
    ↓
喂给下一个 Agent / 工作流
    ↓
做批量统计（1000 条评论的情感分布）
```

结构化输出的三个层次（今天必须亲手对比）：

```text
① Prompt 约定
   “请返回 JSON”
   → 模型大概率照做，但可能加解释、加 ```json 代码块、漏字段
   → 最脆弱

② JSON Mode（ChatResponseFormat.Json）
   → 模型被约束为“只能输出合法 JSON”
   → 但不保证字段名、字段类型、字段齐全

③ JSON Schema（ChatResponseFormatJson / GetResponseAsync<T>）
   → 模型被约束为“输出符合指定 Schema 的 JSON”
   → SDK 自动反序列化成 C# 对象
   → 最可靠（但模型仍不保证 100% 遵守，需要防御）
```

# 8. 实验一：Prompt 约定 JSON（旧办法，故意踩坑）

先写最朴素的方式：在 Prompt 里“请求” JSON。

`Program.cs`：

```csharp
using System.ComponentModel;
using System.Text;
using System.Text.Json;
using Microsoft.Extensions.AI;
using Microsoft.Extensions.Configuration;
using OpenAI;
using System.ClientModel;

// ===== 中文控制台输入乱码修复（中文 Windows 控制台代码页 936 / GBK）=====
Encoding.RegisterProvider(CodePagesEncodingProvider.Instance);
Console.InputEncoding = Encoding.GetEncoding(936);

IConfigurationRoot config = new ConfigurationBuilder()
    .AddUserSecrets<Program>()
    .Build();

string? model = config["DashScopeModel"];
string? key = config["DashScopeKey"];

// 阿里云百炼（DashScope）兼容 OpenAI 接口
OpenAIClientOptions clientOptions = new()
{
    Endpoint = new Uri("https://dashscope.aliyuncs.com/compatible-mode/v1")
};

IChatClient client =
    new OpenAIClient(new ApiKeyCredential(key!), clientOptions)
        .GetChatClient(model)
        .AsIChatClient();

// OpenAI 官方接口的用户改用：
// IChatClient client =
//     new OpenAIClient(key!)
//         .GetChatClient(model)
//         .AsIChatClient();

string article = """
    RAG（检索增强生成）是一种把外部知识库与大模型结合的技术。
    系统先把文档切分、向量化并存入向量数据库；
    用户提问时，先检索相关片段，再把片段连同问题一起交给大模型生成答案。
    RAG 能显著降低模型幻觉，并让答案可溯源。
    """;

string prompt = $"""
    请阅读下面的文章，并返回一个 JSON 对象，包含：
    - title：文章标题
    - summary：100 字以内中文摘要
    - keywords：3 到 5 个关键词的数组

    文章：
    {article}
    """;

ChatResponse response = await client.GetResponseAsync(prompt);

Console.WriteLine("=== 模型原始返回 ===");
Console.WriteLine(response.Text);
Console.WriteLine();

// 程序想直接用，就得自己反序列化
try
{
    ArticleSummary? result =
        JsonSerializer.Deserialize<ArticleSummary>(
            response.Text,
            new JsonSerializerOptions { PropertyNameCaseInsensitive = true });

    Console.WriteLine("=== 反序列化成功 ===");
    Console.WriteLine($"标题：{result?.Title}");
    Console.WriteLine($"关键词：{string.Join("、", result?.Keywords ?? [])}");
}
catch (JsonException ex)
{
    Console.WriteLine($"=== 反序列化失败：{ex.Message} ===");
    Console.WriteLine("这就是“Prompt 约定”的脆弱性。");
}

// 定义我们想要的输出结构。
// 注意：使用 top-level statements 时，类型声明必须放在所有语句之后。
public class ArticleSummary
{
    [Description("文章标题")]
    public string? Title { get; set; }

    [Description("100 字以内的中文摘要")]
    public string? Summary { get; set; }

    [Description("3 到 5 个关键词")]
    public List<string>? Keywords { get; set; }
}
```

运行：

```powershell
dotnet run
```

### 预期与观察

多运行几次，你大概率会遇到下面两种“坑”之一：

1. 模型返回了 Markdown 代码块：

   ````text
   ```json
   {
     "title": "RAG 简介",
     ...
   }
   ```
   ````

   此时 `JsonSerializer.Deserialize` 直接抛异常，报错类似：

   ```text
   '`' is an invalid start of a value. LineNumber: 0 | BytePositionInLine: 0.
   ```

   （这是真实存在的失败模式：模型把 JSON 包在 ```json 围栏里，第一个字符是反引号 `` ` ``，不是合法 JSON 起始。）

2. 模型在 JSON 前后加了“好的，以下是结果：”之类的说明文字。

把你实际遇到的现象记录到 `troubleshooting.md`。

### 必须得出的结论

```text
Prompt 约定 JSON
    ↓
模型“听懂了”，但输出格式不受强制约束
    ↓
程序侧解析不稳定
```

# 9. 实验二：JSON Mode —— ChatResponseFormat.Json

现在不给模型“自由发挥”，而是通过 `ChatOptions.ResponseFormat` 要求它只能输出 JSON。

修改请求部分：

```csharp
ChatOptions options = new()
{
    ResponseFormat = ChatResponseFormat.Json,
    Temperature = 0.2f
};

ChatResponse response = await client.GetResponseAsync(prompt, options);

Console.WriteLine("=== 模型原始返回 ===");
Console.WriteLine(response.Text);
Console.WriteLine();

ArticleSummary? result =
    JsonSerializer.Deserialize<ArticleSummary>(
        response.Text,
        new JsonSerializerOptions { PropertyNameCaseInsensitive = true });

Console.WriteLine($"标题：{result?.Title}");
Console.WriteLine($"摘要：{result?.Summary}");
Console.WriteLine($"关键词：{string.Join("、", result?.Keywords ?? [])}");
```

运行并观察。

### 两个关键注意点

**注意点 1：Prompt 里要出现 “json” 字样。**

OpenAI 与百炼兼容模式都要求：使用 JSON 模式时，Prompt 中必须显式提到 “json”（例如“请返回 JSON”）。否则可能直接返回 400 错误。我们的 Prompt 里已经写了“返回一个 JSON 对象”，满足要求。

**注意点 2：JSON Mode 只保证“是合法 JSON”，不保证“结构正确”。**

你可以故意做一次对比：把 Prompt 里的字段要求改成只让它返回 `title`，然后仍然反序列化成 `ArticleSummary`——程序不报错，但 `Summary`、`Keywords` 是 `null`。

结论：

```text
ChatResponseFormat.Json
    ↓
保证：输出是合法 JSON
不保证：字段名、字段类型、字段齐全
```

# 10. 实验三：看见 Schema —— AIJsonUtilities.CreateJsonSchema

在进入“带 Schema 的请求”之前，先亲眼看一下：C# 类型是怎么变成 JSON Schema 的。

新增代码：

```csharp
JsonElement schema =
    AIJsonUtilities.CreateJsonSchema(
        typeof(ArticleSummary),
        description: "文章摘要的结构化结果");

Console.WriteLine("=== 自动生成的 JSON Schema ===");
Console.WriteLine(
    JsonSerializer.Serialize(
        schema,
        new JsonSerializerOptions { WriteIndented = true }));
```

运行，你会看到类似：

```json
{
  "type": "object",
  "description": "文章摘要的结构化结果",
  "properties": {
    "title": {
      "type": "string",
      "description": "文章标题"
    },
    "summary": {
      "type": "string",
      "description": "100 字以内的中文摘要"
    },
    "keywords": {
      "type": "array",
      "items": { "type": "string" },
      "description": "3 到 5 个关键词"
    }
  }
}
```

观察重点：

1. 类名、属性名变成了 Schema 字段。
2. `[Description("...")]` 的文字进入了 Schema 的 `description`——**这就是模型理解字段含义的依据**，所以描述要写清楚。
3. `List<string>` 自动变成 `"type": "array"`。
4. 可空引用类型（`string?`）会影响字段是否必填。

> 这一步建立的认知：**C# 类型 = 输出契约 = JSON Schema 的来源**。你不需要手写 Schema。

# 11. 实验四：带 Schema 的请求 —— ChatResponseFormatJson

把上一步生成的 Schema 放进 `ChatResponseFormatJson`：

```csharp
JsonElement schema =
    AIJsonUtilities.CreateJsonSchema(
        typeof(ArticleSummary),
        description: "文章摘要的结构化结果");

ChatOptions options = new()
{
    ResponseFormat = new ChatResponseFormatJson(
        schema,
        schemaName: "ArticleSummary",
        schemaDescription: "文章摘要的结构化结果"),
    Temperature = 0.2f
};

ChatResponse response = await client.GetResponseAsync(prompt, options);

Console.WriteLine("=== 模型原始返回 ===");
Console.WriteLine(response.Text);

ArticleSummary? result =
    JsonSerializer.Deserialize<ArticleSummary>(
        response.Text,
        new JsonSerializerOptions { PropertyNameCaseInsensitive = true });

Console.WriteLine($"标题：{result?.Title}");
Console.WriteLine($"关键词数量：{result?.Keywords?.Count ?? 0}");
```

### 与实验二对比

| 对比项 | 实验二：JSON Mode | 实验四：JSON Schema |
|---|---|---|
| 输出是合法 JSON | 是 | 是 |
| 字段名受约束 | 否 | 是 |
| 字段类型受约束 | 否 | 是 |
| 字段齐全度 | 模型自由 | 模型按 Schema 生成 |
| 需要手写反序列化 | 是 | 是（下一步被泛型方法替代） |

### 可能遇到的 Provider 差异（重要）

不是所有模型 / Provider 都原生支持“带 Schema 的结构化输出”。如果请求报 400，错误信息里出现 `response_format`、`json_schema`、`not supported` 之类字样：

```text
不要硬刚。
```

这正是 Day004 建立的认知：

```text
统一抽象（IChatClient）
    ≠
所有 Provider 能力一致
```

处理办法：

1. 换用支持结构化输出的模型（如百炼 `qwen-plus` / `qwen-max` 等较新模型）；
2. 或使用下一个实验中泛型方法的“回退模式”；
3. 把模型名、报错原文记录到 `troubleshooting.md`——后面做多 Provider 适配时这是宝贵资料。

# 12. 实验五：今天的主角 —— GetResponseAsync<T>

前面实验四已经能约束结构，但还要自己 `Deserialize`。`Microsoft.Extensions.AI` 提供了泛型扩展方法，一步到位：

```csharp
ChatResponse<ArticleSummary> response =
    await client.GetResponseAsync<ArticleSummary>(
        prompt,
        new ChatOptions { Temperature = 0.2f });

// 推荐写法：先 TryGetResult 做防御
if (response.TryGetResult(out ArticleSummary? result))
{
    Console.WriteLine($"标题：{result.Title}");
    Console.WriteLine($"摘要：{result.Summary}");
    Console.WriteLine($"关键词：{string.Join("、", result.Keywords ?? [])}");
}
else
{
    Console.WriteLine("模型输出无法解析为 ArticleSummary，原始返回：");
    Console.WriteLine(response.Text);
}
```

它替你做了三件事：

```text
① 从 T 自动生成 JSON Schema
② 设置 ResponseFormat（原生支持的 Provider 走 Schema；不支持时库会回退）
③ 把返回的 JSON 反序列化成 T
```

也可以直接访问 `response.Result`：

```csharp
ArticleSummary result = response.Result!;
```

但要知道官方 Remarks 的警告：**模型不保证 100% 遵守 Schema**。`Result` 在解析失败时会抛出异常；生产代码推荐 `TryGetResult` + 失败时记录 `response.Text`。

### 回退参数：useJsonSchemaResponseFormat

泛型方法有一个 `bool? useJsonSchemaResponseFormat` 参数：

```csharp
ChatResponse<ArticleSummary> response =
    await client.GetResponseAsync<ArticleSummary>(
        prompt,
        new ChatOptions { Temperature = 0.2f },
        useJsonSchemaResponseFormat: false);   // 显式回退
```

含义：

```text
true / 默认 null
    → 优先向 Provider 提交 JSON Schema（原生结构化输出）

false
    → 不提交 Schema，改用“JSON Mode + Prompt 指令”，再由库解析
```

如果实验四 / 实验五默认调用在你的模型上报 400，就加 `useJsonSchemaResponseFormat: false` 再试，并记录差异。

# 13. 实验六：枚举 + 业务场景（官方快速入门同款）

官方快速入门用的是“产品评论情感分析”。我们做一遍，并引入**枚举**。

在 `Program.cs` **末尾**（top-level 语句之后）定义类型：

```csharp
public enum Sentiment
{
    Positive,   // 正面
    Negative,   // 负面
    Neutral     // 中性
}

public class ReviewAnalysis
{
    [Description("情感倾向，只能是 Positive、Negative、Neutral 之一")]
    public Sentiment Sentiment { get; set; }

    [Description("0 到 10 的情感强度评分，整数")]
    public int Score { get; set; }

    [Description("一句话中文结论")]
    public string? Conclusion { get; set; }
}
```

准备 3 条评论，批量分析：

```csharp
string[] reviews =
[
    "这个产品太好用了！物流第二天就到，客服也很耐心，强烈推荐。",
    "质量很差，用了两天就坏了，客服还不理人，非常失望。",
    "东西收到了，包装完好，目前用着还行，以后再追评。"
];

foreach (string review in reviews)
{
    string reviewPrompt = $"""
        请分析下面这条产品评论，并以 JSON 格式输出结构化结果。

        评论：{review}
        """;

    ChatResponse<ReviewAnalysis> response =
        await client.GetResponseAsync<ReviewAnalysis>(
            reviewPrompt,
            new ChatOptions { Temperature = 0.1f });

    if (response.TryGetResult(out ReviewAnalysis? r))
    {
        Console.WriteLine(
            $"评论：{review}");
        Console.WriteLine(
            $"  → 情感：{r.Sentiment}，评分：{r.Score}/10，结论：{r.Conclusion}");
        Console.WriteLine();
    }
    else
    {
        Console.WriteLine($"解析失败：{response.Text}");
    }
}
```

### 预期

```text
评论：这个产品太好用了！……
  → 情感：Positive，评分：9/10，结论：用户非常满意……

评论：质量很差……
  → 情感：Negative，评分：1/10，结论：用户强烈不满……

评论：东西收到了……
  → 情感：Neutral，评分：5/10，结论：用户态度中性……
```

### 观察点

1. 枚举不是字符串乱飞——模型输出 `"Positive"`，SDK 自动转成 `Sentiment.Positive`，程序里可以直接 `switch`。
2. `Temperature = 0.1f`：结构化任务追求**稳定、可复现**，低温度更合适（呼应 Day004）。
3. 这就是“把 1000 条评论跑出情感分布图”的起点——输出是数据，才能批量统计。

> 说明：泛型方法支持基元类型、数组、枚举和复杂类型；但 `ResponseFormat`（手动指定格式）的方式不支持顶层基元/数组。今天统一用泛型方法即可。

# 14. 实验七：结构化输出 + Streaming（衔接 Day005）

结构化输出和流式输出不是二选一。思路：**用 JSON Mode 流式拿到文本，累积后反序列化**。

```csharp
ChatOptions options = new()
{
    ResponseFormat = ChatResponseFormat.Json,
    Temperature = 0.2f
};

string streamPrompt = $"""
    请阅读下面的文章，以 JSON 格式输出结构化结果，
    包含 title（标题）、summary（摘要）、keywords（关键词数组）。

    文章：{article}
    """;

string fullText = "";

Console.WriteLine("=== 流式接收 JSON ===");
await foreach (ChatResponseUpdate update in
    client.GetStreamingResponseAsync(streamPrompt, options))
{
    Console.Write(update.Text);   // 边生成边显示
    fullText += update.Text;
}
Console.WriteLine();

// 流结束后，整体反序列化
ArticleSummary? streamed =
    JsonSerializer.Deserialize<ArticleSummary>(
        fullText,
        new JsonSerializerOptions { PropertyNameCaseInsensitive = true });

Console.WriteLine();
Console.WriteLine($"=== 结构化结果 ===");
Console.WriteLine($"标题：{streamed?.Title}");
Console.WriteLine($"关键词：{string.Join("、", streamed?.Keywords ?? [])}");
```

### 必须理解的点

```text
流式（Day005）解决：结果怎么“到达”
结构化（Day006）解决：结果长什么“形状”

二者正交，可以组合：
    流式到达 + 累积完整 JSON + 反序列化
```

注意：**JSON 只有在完整时才能反序列化**——流式过程中半截 `{"title":"RAG` 是无法解析的，必须等流结束。这也是为什么后面做前端时，通常要么流式显示文本、要么等完整 JSON 再渲染组件。

# 15. 实验八：失败与防御（必做）

结构化输出不是“银弹”，故意制造两次失败，建立防御意识。

## 15.1 MaxOutputTokens 太小 → JSON 被截断

```csharp
ChatResponse<ArticleSummary> response =
    await client.GetResponseAsync<ArticleSummary>(
        prompt,
        new ChatOptions
        {
            Temperature = 0.2f,
            MaxOutputTokens = 60   // 故意给很小
        });

Console.WriteLine($"原始返回：{response.Text}");
Console.WriteLine($"TryGetResult：{response.TryGetResult(out _)}");
```

现象：JSON 生成到一半被切断（例如 `keywords` 数组没闭合），`TryGetResult` 返回 `false`。

结论：

```text
结构化输出要给足 MaxOutputTokens 预算
    ↓
Token 预算是结构化输出可靠性的一部分（Day011 会系统学 Token）
```

## 15.2 模型不遵守 Schema 时怎么办

官方已经明说模型不保证 100% 遵守。防御套路：

```csharp
if (response.TryGetResult(out ArticleSummary? result))
{
    // 正常路径：用强类型对象
    SaveToDatabase(result);
}
else
{
    // 失败路径：记录原始文本，便于排查 / 重试 / 降级
    _logger.LogWarning("结构化输出解析失败：{Text}", response.Text);
    // 生产中可以：重试一次 / 换模型 / 退回纯文本展示
}
```

今天在控制台里把失败分支的 `response.Text` 打印出来即可。

## 15.3 实验一的“代码块围栏”怎么救

如果回到实验一那种 Prompt 约定方式，模型返回了 ```json 围栏，最小兜底是提取第一个 `{` 到最后一个 `}` 之间的内容：

```csharp
static string ExtractJson(string text)
{
    int start = text.IndexOf('{');
    int end = text.LastIndexOf('}');
    return start >= 0 && end > start
        ? text.Substring(start, end - start + 1)
        : text;
}
```

但今天学完后你应该明白：**更好的做法不是写更多字符串补丁，而是直接用 JSON Mode / Schema / 泛型方法**。

# 16. 三层方案对比总结

| 层次 | 怎么用 | 保证什么 | 不保证什么 | 适用 |
|---|---|---|---|---|
| ① Prompt 约定 | Prompt 里写“返回 JSON” | 无强制 | 合法 JSON、字段都不保证 | 只适合 Demo |
| ② JSON Mode | `ResponseFormat = ChatResponseFormat.Json` | 输出是合法 JSON | 字段名/类型/齐全 | 结构简单、容忍缺字段 |
| ③ JSON Schema | `ChatResponseFormatJson(schema)` 或 `GetResponseAsync<T>()` | 输出符合 Schema 并可反序列化 | 模型仍有小概率不遵守（需 `TryGetResult`） | **生产首选** |
